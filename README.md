# سپیدار | SEPIDAR Restaurant Platform

مخزن اصلی پروژه سفارش غذای سپیدار.

## اجزای مخزن

- `index.html`: رابط فعلی سایت مشتریان؛ در راه‌اندازی زیرساخت سرور تغییری در آن داده نشده است.
- `worker/`: نقطه شروع بک‌اند Cloudflare Workers و تنظیمات لازم برای استقرار آن.

## وضعیت فعلی سرور

بک‌اند فعلاً یک اسکلت اولیه برای بررسی سلامت سرویس دارد. مسیرهای فعلی:

- `GET /`: اطلاعات پایه وضعیت سرویس.
- `GET /health`: بررسی سلامت سرویس.

**ثبت سفارش واقعی، پایگاه داده، ورود امن، پنل رستوران، نظرات و سایر APIهای تجاری هنوز در این اسکلت پیاده‌سازی نشده‌اند.** این موارد باید در مراحل بعدی به‌صورت کامل طراحی، پیاده‌سازی و آزمایش شوند؛ وجود این فایل‌ها به معنی آماده بودن سامانه برای دریافت سفارش واقعی نیست.

## آماده‌سازی اتصال GitHub به Cloudflare Workers

تنظیمات Worker در `worker/wrangler.jsonc` قرار دارد. هنگام اتصال مخزن در داشبورد Cloudflare:

1. وارد **Workers & Pages** شوید و **Create application** را انتخاب کنید.
2. مسیر **Import a repository** را انتخاب و دسترسی GitHub را تأیید کنید.
3. مخزن `hosseinasgari898989-dev/sepidar-restaurant-platform` و شاخه `main` را انتخاب کنید.
4. مقدار **Root directory** را `worker` قرار دهید تا Cloudflare از تنظیمات و کد بک‌اند داخل همین پوشه استفاده کند.
5. نام Worker را دقیقاً مطابق مقدار `name` در `worker/wrangler.jsonc`، یعنی `sepidar-restaurant-api`، انتخاب کنید.
6. در صورت نیاز، دستور استقرار را `npx wrangler deploy` قرار دهید؛ دستور ساخت جداگانه‌ای برای اسکلت فعلی لازم نیست.
7. تنظیمات را ذخیره و استقرار را اجرا کنید. بعد از موفقیت، آدرس عمومی `workers.dev` را برای آزمایش مسیرهای سلامت بررسی کنید.

اگر Worker را از قبل ساخته‌اید، می‌توانید از **Settings → Builds → Connect** برای اتصال مخزن استفاده کنید. نام Worker در داشبورد باید با نام موجود در تنظیمات Wrangler هماهنگ باشد.

راهنمای رسمی Cloudflare: [Git integration](https://developers.cloudflare.com/workers/ci-cd/builds/git-integration/) و [Build configuration](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/).

## نکات مهم

- این مخزن عمداً از Git integration خود Cloudflare استفاده می‌کند؛ برای این روش، الزاماً نیازی به نگهداری توکن استقرار Cloudflare در GitHub Actions نیست.
- هیچ توکن، رمز یا کلید محرمانه‌ای را در فایل‌های این مخزن قرار ندهید.
- فهرست مبدأهای مجاز مرورگر فعلاً شامل دامنه GitHub Pages حساب و آدرس‌های توسعه محلی است. اگر دامنه نهایی سایت تغییر کرد، مقدار `ALLOWED_ORIGINS` باید بازبینی شود.
- هنوز پایگاه داده D1 ساخته یا به Worker متصل نشده است. شناسه واقعی پایگاه داده باید پس از ساخت آن در Cloudflare به تنظیمات Worker افزوده شود.
- پیش از استفاده عمومی برای سفارش واقعی، باید APIهای تجاری، احراز هویت، اعتبارسنجی سمت سرور، کنترل دسترسی رستوران‌ها، محدودسازی درخواست‌ها و آزمون‌های امنیتی تکمیل شوند.
